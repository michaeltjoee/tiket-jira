Reference · Query keys

Sprint board cache

Compressed map of the two QueryClient entries the ledger reads. UI always reads memory; localStorage is a snapshot.

Keys

SPRINT_BOARD_QUERY_KEY

["sprint-board"] prefix.
Full: sprintBoardQueryKey(id) → ["sprint-board", id]
id: "active" | number
Data: SprintBoardData
Source: GET /api/sprint-board

SPRINT_BOARD_META_QUERY_KEY

["sprint-board-meta"] exact, singleton.
Data: { activeNumber, recentSprints }
Source: first cacheSprintBoardResponse only
Observed with enabled: false

Who writes what

fetchSprintBoardAndCache(queryClient, sprintNumber?)
  fetchSprintBoard          → GET /api/sprint-board[?sprint=n]
  cacheSprintBoardResponse
    setQueryData(["sprint-board", data.sprint.number], data)
    if meta empty:
      setQueryData(["sprint-board-meta"], { activeNumber, recentSprints })
    pruneSprintBoardQueries → keep last 5 board ids

What the hook observes

boardId = sprintNumber ?? "active"
useQuery(["sprint-board-meta"], enabled: false)
useQuery(["sprint-board", boardId],
         queryFn: fetchSprintBoardAndCache,
         enabled: !isRestoring)

data.recentSprints = meta?.recentSprints ?? board.recentSprints

When the network runs

  • First visit to a board id not in memory (including "active" on a cold cache).
  • Refresh: clearPersistedSprintBoard cancels, drops meta, deletes sprint-board:v1, resetQueries on the board prefix.
  • Not on return to a filled key — staleTime: Infinity, no refetch on mount/focus.

Glossary

Board body. Parents, effort, timestamps for one sprint. May include a recentSprints field from Jira; the UI must not trust that field after the first seed.

Bootstrap key. ["sprint-board", "active"] — used when the URL has no number yet. The numeric alias is written so ?sprint=42 later hits memory.

Seed-once meta. First successful board response fills the picker. Later boards do not overwrite it.

Overlay. Hook replaces board.recentSprints with meta.recentSprints before SprintLedger renders.

Prefix match. queryKey: ["sprint-board"] matches every board id, not meta. See Query Invalidation.
