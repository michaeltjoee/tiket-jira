Lesson 0001 · Sprint ledger cache

Two keys, one ledger fetch

The sprint ledger is not one React Query cache. It is a family of board bodies plus a picker singleton. Both are filled by the same network call. That split is the whole design.

The problem the split solves

Switching sprints must change the table (parents, effort, dates) without changing the dropdown. If the picker were read from whichever board just arrived, an older sprint would rewrite “what is active” and the list under it. The in-tree contract is lib/query/sprint-board.md.

SPRINT_BOARD_QUERY_KEY

Prefix ["sprint-board"]. Full key is ["sprint-board", id] where id is "active" or a number. Holds SprintBoardData — the ledger currently on screen. Several of these can exist (capped at five).

SPRINT_BOARD_META_QUERY_KEY

Exact key ["sprint-board-meta"]. Holds SprintBoardMeta — activeNumber (what “Active sprint” means) and recentSprints (the dropdown). One entry. Never fetched on its own.

TanStack Query treats a key as the identity of cached data. If the query function depends on a variable, that variable belongs in the key — otherwise two sprints would overwrite each other. Query Keys docs. Prefix matching then lets findAll({ queryKey: ["sprint-board"] }) see every board without seeing meta. TkDodo on key factories.

The fetch path

  1. /sprint reads ?sprint=. parseSprintParam yields a number or undefined.
  2. useSprintBoard(sprintNumber) observes two queries: meta with enabled: false, and the board with sprintBoardQueryKey(sprintNumber ?? "active").
  3. Board queryFn calls fetchSprintBoardAndCache → GET /api/sprint-board (optional ?sprint=).
  4. The route calls loadSprintBoard: resolve the Sphinx sprint on the Jira board, build the recent window, fetch parents and subtasks.
  5. On success, cacheSprintBoardResponse writes the body under the numeric key, seeds meta only if meta is empty, then prunes extra boards.
  6. The hook overlays meta.recentSprints onto the current board before the UI sees it. The picker stays put; the table moves.

Persist is a snapshot of this in-memory QueryClient, not a second store. useIsRestoring keeps the board query disabled until localStorage has been hydrated, so a reload does not race a fetch against restore. persistQueryClient. Next lesson, if you want it.

Why meta’s queryFn throws

enabled: false means: subscribe to whatever is already in the cache; do not fetch. Disabling queries. Meta has no endpoint. Board responses setQueryData it. The throwing queryFn is a tripwire — if something ever enables that query, it fails loudly instead of inventing a second fetch.

The seed is one-shot: if (!queryClient.getQueryData(SPRINT_BOARD_META_QUERY_KEY)). Later fetches (closed sprint, refetch of Active) must not replace “what is active.” Hard refresh is the exception: clearPersistedSprintBoard removes meta so the next board response can write a fresh picker.
